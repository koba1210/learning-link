# Learning Link

社内で同じテーマを学ぶ仲間を見つける、レビュー用のWebアプリです。既存プロジェクトから独立した React + Vite + CSS の新規実装です。認証・外部API・サーバー保存はありません。

## GitHub Pages

公開先：<https://koba1210.github.io/learning-link/>

`main` へのpush後、GitHub Actionsが依存関係のインストール、テスト、Lint、ビルドを実行し、`dist/` をGitHub Pagesへ公開します。リポジトリの Settings → Pages → Source は **GitHub Actions** を選択します。`vite.config.js` の `base` は `/learning-link/` です。リポジトリ名を変更する場合はここも変更してください。

公開デモではプロフィール登録・仲間の推薦に加え、勉強会作成、架空の空き時間カレンダー、出欠回答、参加実績とキャラクターの成長を試せます。社員切り替えはデモ操作で、本人認証ではありません。カレンダーの実連携、招待の送信、会議室予約は行いません。

登録内容はブラウザー内のlocalStorageだけに保存され、他の利用者や端末には共有されません。プロフィールのほか、`meetings`、成長通知の確認状態、クリア直前のバックアップもブラウザー内に保持されます。ローカル版と公開版は保存先が異なるため、ローカルで入力した内容は公開版に引き継がれません。公開デモの入力には架空の名前・予定・URLを使用してください。

## レビュー手順

1. 初回画面で未入力のまま登録を押す。表示名とテーマの入力案内が表示され、最初のエラー項目にフォーカスします。
2. 表示名に「田中 美咲」、テーマに「Python」を選び、任意欄は空のまま登録。同じテーマの2人が検索なしで表示されます。同名の別社員「田中 美咲」を含み、本人は含まれません。佐藤 健太の学習目的は「未登録」です。
3. プロフィール編集を開き、現在の内容を確認。名前やテーマを変えてキャンセルし、元の登録とおすすめが変わらないことを確認します。
4. 編集でテーマを「SQL」に変更し、「一緒に学びたいこと」を入力して保存。完了通知と、SQLを学ぶ鈴木 遥・田中 美咲の2人に入れ替わることを確認します。Pythonの社員は表示されません。
5. 再読み込みし、表示名・テーマ・任意欄が残ることを確認します。IDも保存・編集時に維持されます。
6. テーマを「基本情報技術者」に変更して保存。「同じテーマを学習中の社員はまだいません」と登録テーマ、編集ボタンが表示されます。
7. PC幅とスマートフォン幅で編集・保存・キャンセル・カード確認を試します。Tabで移動、矢印キーまたはSpaceでテーマ選択、Enterでフォーム送信ができます。

初回登録を再度確認するときは、別のブラウザープロファイルまたはこのオリジンの保存データを持たない環境を利用してください。プレビューで使ったIABのオリジンには動作確認用プロフィールが保存されています。

## 実装と保存

- `src/model.js`：社員デモデータ、入力検証、IDによる本人除外とテーマ一致による推薦、保存・読込。
- `src/App.jsx`：初回登録・編集・推薦・該当者なし・読み込みエラー。
- `src/styles.css`：PCとスマートフォンのレスポンシブ表示。
- localStorageキー `learning-link.profile.v1` に `{ id, name, topic, goal }` を保存。初回保存時に `crypto.randomUUID()` でIDを作成し、以後は維持します。
- 読み込み失敗・破損データは「未登録」や「0人」と区別し、既存データの上書きを避け、再試行を表示します。自動削除はしません。
- 保存失敗では入力内容を残し、原因候補と再試行方法を表示します。保存成功前には登録済みプロフィールを変更しません。
- 表示名は前後空白を除き1〜40文字、任意欄は300文字以内。Reactのテキスト表示を使い、入力をHTMLとして解釈しません。
- 架空社員6人はソースに固定。Python 2人、SQL 2人、生成AI 1人、AWS認定1人、基本情報技術者0人。表示順は固定で、AI・スコアは利用しません。

## 制限・仮定とチームでの判断事項

- **レビュー用の単一ユーザーを想定。実際の社内共有はできません。** 同じブラウザー・同じオリジンだけで登録内容を保持し、他社員・端末・ブラウザーには共有しません。別ポートも別オリジンです。
- ブラウザーの保存データ削除や一部のプライベートモードではプロフィールとIDが失われます。サーバーバックアップはありません。複数タブの同時編集は後から保存した内容が優先されます。
- 部署名は相手の見分けやすさのため架空データにのみ付与し、入力項目には追加していません。
- 1人1テーマ、表示名の重複可、任意項目未入力可を採用しています。
- 本番化では社員IDと既存認証の接続、社内共有用の保存基盤、閲覧範囲、個人情報の保存・削除方針、テーマ候補の管理をチームで決定してください。
- 検索・メッセージ・募集・通知・ランキング・進捗管理は実装していません。
